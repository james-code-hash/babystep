# 小步 Little Steps — 開發交接（給 Claude Code）

> 這份文件寫給接手開發的 coding agent。
> 寫法刻意是「目標 + 少數不可違反的底線 + 大量留白」，**不是**逐條規格。
> 你被期待自己做技術與設計判斷。只有違反底線的時候才需要停下來問人。

---

## 0. 一分鐘讀懂

**做什麼：** 一款給 6–12 歲孩子的成長 App。孩子每天自己決定今天要做的 1–3 件小事，寫成「如果⋯我就⋯」，晚上誠實回顧，並把今天的經驗「教」給一隻叫步步的小寵物。

**為什麼不一樣：** 市面上的同類產品都用集點、連續打卡、排行榜。這款**刻意不用**——它要保護的是孩子的內在動機，不是讓孩子乖乖完成任務。

**成功長什麼樣：** 孩子覺得「這是我自己決定、自己做到的」，最終不太需要這個 App。

**你的第一個目標：** 做出一個能在真實裝置上、離線跑完一整天核心循環的 MVP（見 §4）。其他都是你的判斷空間。

## 2. 不可違反的底線（只有這些是硬性的）

這是整個產品存在的理由。其他所有東西都可以改，這幾條不行。如果某個需求或你的設計會碰到它們，**停下來問人**。

1. **沒有外部酬賞結構。** 不做點數、金幣、徽章、等級、排行榜、連續天數（streak），也不做「完成 N 件解鎖 X」。任何東西都不能用完成度兌換。
2. **步步的狀態永遠不取決於孩子做了什麼。** 牠不會因為孩子沒做而生病、難過、變弱、消失，外觀也不會因為孩子完成任務而升級。外觀只能因為孩子主動裝扮、時間推移、季節而改變。
3. **不用罪惡感，也不挽留。** 不能出現「我等你好久」「你好久沒來」「不要走嘛」這類句子，也不做 FOMO 或急迫感推播。隔多久沒打開，步步的語氣都一樣。
4. **「今天沒做」必須完全中性。** 視覺權重與「做到了」相同，選了不會有任何後果（不扣分、不通知家長、步步不失望）。在步步的「學到一件事」裡，這一天也要學得到東西，否則「學習」就退化成新的酬賞。
5. **只讚美過程，不評價人。** 產品裡任何一句話（包括 LLM 生成的）都不能說「你好聰明／好棒／厲害／天才」，也不能出現結果讚美與命令式提醒。
6. **計畫由孩子自己產生。** 系統和步步可以提問、給選項，但不能替孩子寫好計畫內容。家長建議的事項，孩子有權不選。
7. **家長不是監控者。** 家長端不顯示完成率、使用時長、趨勢圖、孩子的心情，也不顯示孩子沒主動分享的內容。分享是孩子主動做的動作，不是預設值。
8. **兒童資料安全。** 本地優先，不放第三方追蹤或廣告 SDK，沒有內購誘導，資料可完整匯出與刪除。送去 LLM 的資料只放當次需要的最小內容，供應商端設為不保留、不拿來訓練。
9. **危機內容不交給 LLM 即興處理。** 孩子的輸入若出現自傷、受虐、嚴重情緒困擾的訊號，就切換到預先寫好的安全回應路徑。

**建議做法（不強制）：** 把這些底線變成程式裡的檢查，不要只留在文件裡。比如寫一個文案 lint 掃所有字串和 LLM 輸出；寫一條測試證明寵物的狀態 model 不依賴完成紀錄；寫一條測試確認家長端 API 回傳的資料裡沒有完成率欄位。有了這些護欄，你在其他地方可以放手改。

## 3. 你可以自由決定的事

下面這些在原文件裡寫得很具體，但**全部是建議，不是規格**。依你的判斷改，記下理由就好。

- **技術棧與架構**：Flutter、React Native、原生、PWA 都可以。後端要不要有、狀態管理、資料庫、同步策略也由你決定。唯一的要求是核心循環能離線跑。
- **資訊架構與畫面數量**：原型有 11 個畫面、5 個 tab，你可以合併、拆分或重新排。
- **具體數字**：每天最多 3 件、提醒每天最多 2 次、步步一句話 60 字以內、LLM 重試 2 次、延遲 3 秒／8 秒換 fallback……這些都是起始值，要做成好調整的設定，依實測結果調整。
- **文案**：可以重寫、擴充、改得更好笑，只要過得了文案庫第七章的檢核表和 §2 第 5 條。
- **步步的視覺與動畫**：企劃建議用 2D、Q 版、圓潤造型，細節由你設計。
- **成長軌跡怎麼呈現**：地圖、樹、星空或你想到的新形式都可以，只要沒做的日子不顯示成斷點或空洞。
- **LLM 的防護設計**：原文件的「prompt 約束 + 關鍵字過濾 + 範本 fallback」是一種做法。你可以改用 classifier、structured output、第二個模型當評審，或任何更可靠的方式。provider 也由你選。
- **分齡（6–8 歲／9–12 歲）**：MVP 要先做哪一組、怎麼切換，由你決定。
- **MVP 以外的模組**（探索角、驚喜盒、塗鴉、月回顧、家長話術轉譯器、全家一起成長）：做不做、什麼時候做，由你排優先順序。
- **測試策略、資料夾結構、CI**：自己決定。

如果你覺得某個核心設計本身有問題（例如 if-then 流程對 6 歲孩子太難），可以提出替代方案並直接做出可比較的版本，不必等人批准。

## 4. MVP 的完成定義

用結果來描述，怎麼做到由你決定：

- [ ] 在真實手機或平板上，孩子可以**離線**跑完一整天：早上選 1–3 件事 → 寫成「如果⋯我就⋯」→（選填）為什麼 → 晚上回顧三種狀態 → 回答一個歷程問題（可跳過）→ 步步說牠學到的一件事（可能是「今天沒什麼特別要記的」）→ 得到明確的結束。
- [ ] 「今天沒做」的路徑和「做到了」一樣完整，步步在這兩種情況下都能學到東西。
- [ ] 步步學到的內容會累積成一本筆記，可以翻閱，不顯示數量也不設目標。
- [ ] 有一個能看出「自己在長大」的地方，只跟自己比。
- [ ] 家長可以設定給孩子挑的事情範本與時間點範本（原型的「家長設定」頁就是這個範圍）。
- [ ] 「步步學到」有兩種模式：離線時用範本，連線時用 LLM。LLM 失敗或逾時要無痛退回範本，家長可以關掉 LLM。
- [ ] §2 的底線有自動化檢查，並且全部通過。
- [ ] 有一份簡短 README，寫清楚怎麼跑、怎麼測、你做了哪些主要決策。

不在 MVP 範圍內（除非你判斷順手而且不影響上面幾項）：帳號系統、雲端同步、付費、多孩子、推播通知。

## 5. 已知的開放問題（交給你判斷）

這些是企劃階段還沒解決的問題。選一個方向往前推，在 decision log 裡寫下你的選擇與理由。

1. **孩子通常沒有自己的手機。** App 是裝在家長手機、家用平板，還是兩者都要支援？白天的提醒要怎麼送到孩子面前？（原型目前的假設是：由家長設定時段，孩子打開 App 時步步會探頭提醒。）
2. **低年級的「書寫」問題。** 6–8 歲的孩子打字有困難，可以考慮圖像選單、語音輸入或注音輸入。語音會牽涉兒童語音資料的隱私問題，需要權衡。
3. **LLM 的輸入來源。** 孩子的回答很短的時候，LLM 能提取的內容有限。要不要結合當天的計畫內容？要結合到什麼程度才不會變成「編造」？
4. **家長端的形式。** 同一個 App 切換模式、獨立 App，還是網頁？MVP 階段可以先用同一個 App 加一道家長鎖。
5. **年齡切換的時機。** 由家長設定、由孩子自己選，還是兩者都可以？

## 6. 工作方式

- **做決定，然後記錄。** 在 repo 裡放一份 `docs/decisions.md`（或 ADR 資料夾），每個重要的選擇用三到五行寫清楚：選了什麼、考慮過哪些替代方案、為什麼這樣選。這份紀錄取代「事前請示」。
- **小步快跑。** 先讓核心循環能跑通，再打磨細節。比起一次寫完的完美架構，一個能在裝置上點完整天流程的醜版本更有價值。
- **需要停下來問人的情況**（只有這些）：
  - 會碰到 §2 任何一條底線
  - 需要收集真實兒童資料、做真人測試，或串接需要付費的外部服務
  - 法規與合規判斷（台灣個資法、COPPA 等）
  - 產品方向的根本改變（例如想拿掉 if-then 或拿掉步步）
- **其他情況都不必問**，直接做，在交付說明裡交代清楚即可。

## 7. 一句話版本

> 守住 §2 的底線，讓孩子一天能跑完「自己決定 → 自己做 → 誠實回顧 → 教步步」這個循環，其他都交給你的判斷。
