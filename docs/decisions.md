狀態標記：✅ 已定　🔁 起始值待實測　⏸ 需要人決定（HANDOFF §6）

## A. 技術棧

### A1 ✅ 前端：Flutter（iOS + Android），fvm 釘 3.47.6
- **選擇**：Flutter，單一 codebase 出 iOS/Android；以 `.fvmrc` 釘版本。
- **替代**：React Native（JS 生態豐富但步步的向量繪圖與動畫要靠第三方）、原生雙寫（成本 ×2）、PWA（離線、通知、上架受限）。
- **理由**：產品方指定；CustomPainter 很適合畫步步這種向量角色、動畫可控；離線本地資料庫成熟。

### A2 ✅ 後端：Firebase，但只做「LLM 代理」這一件事
- **選擇**：孩子的資料全部存在裝置上。Firebase 只用 Cloud Functions（callable `bubuLearn`）＋ Anonymous Auth ＋ App Check，作為 LLM 的代理層。不用 Firestore 存孩子資料，不用 Analytics／Crashlytics。
- **替代**：(a) Firestore 離線持久化當主資料庫——但資料會預設上雲，違反 §2.8 本地優先；(b) 客戶端直接用 Firebase AI Logic 呼叫模型——prompt、過濾規則都在客戶端、易被繞過，伺服器端無法再加一層過濾；(c) 自架伺服器——多一套維運。
- **理由**：底線 8 要求本地優先、最小傳輸。代理層讓 prompt／過濾／回溯檢查留在伺服器、App 再過濾一次（雙層），而且 API 金鑰不進 App。Analytics／Crashlytics 屬追蹤 SDK，不放。

### A3 ⏸ LLM 供應商：Vertex AI 上的 Gemini（同一個 GCP 專案），需要 Blaze 方案
- **選擇**：Cloud Function 以服務帳號呼叫 Vertex AI Gemini（小模型，型號用環境參數設定）。供應商層做成可插拔（`functions/src/providers/`），測試用 `fake` provider。
- **替代**：Gemini Developer API 免費層（**會被用於改善模型，違反 §2.8，排除**）；Anthropic／OpenAI 直連（多一個第三方資料處理者與合約）；Claude on Vertex（可行的第二選項，介面已預留）。
- **理由**：Vertex AI 依 Google Cloud 條款不拿客戶資料訓練，資料不離開本專案的 GCP 邊界，不必再簽第三方。
- **待決**：`little-steps-dev` 目前沒有啟用帳單；Cloud Functions 與 Vertex 都需要 Blaze（付費）。依 §6「串接需要付費的外部服務」要先問人。在那之前 LLM 模式只在 Firebase Emulator ＋ fake provider 上跑，App 預設走範本模式，核心循環完全不受影響。另外「供應商端不保留」需要在 GCP 端確認 Vertex 的資料保留／濫用監控設定，屬合規判斷，一併列給人決定。

### A4 ✅ 本地資料庫：drift（SQLite）
- **選擇**：drift，含 schema migration；測試用 in-memory 資料庫。
- **替代**：Hive／Isar（Isar 維護狀況不穩；Hive 無 schema、匯出與遷移較麻煩）、shared_preferences 存 JSON（資料一多就難維護）、sqflite 手寫 SQL（沒有型別）。
- **理由**：型別安全、遷移明確、整包匯出（JSON）與刪除（刪檔）都簡單；SQLite 檔案就在 App sandbox 內。

### A5 ✅ 狀態管理：Riverpod；路由：go_router
- **替代**：Bloc（樣板多）、Provider（較舊）、純 setState（流程跨頁狀態難管理）。
- **理由**：依賴注入方便（測試時換掉 DB、LLM client、時鐘），不需要 codegen。

### A6 ✅ 專案結構
- `app/`（Flutter）、`functions/`（Cloud Functions, TypeScript）、`shared/copy_rules.json`（兩邊共用的文案規則）、`docs/`。
- App 內依功能分：`core/`（config、時鐘、安全規則）、`data/`（drift）、`domain/`（純 Dart 邏輯，可單測）、`features/<畫面>`、`copy/`（所有使用者看得到的句子）、`bubu/`（角色繪製）。

## B. HANDOFF §5 開放問題

### B1 ✅ 裝在哪台裝置、白天提醒怎麼送到孩子面前
- **選擇**：假設主要裝在**家用平板或家長手機（共用裝置）**，同一個 App 同時支援手機與平板版面。白天提醒採「**孩子打開 App 時，步步在首頁探頭**」：家長設定提醒時段（如放學後、吃完晚飯），孩子在那個時段打開 App、且今天有計畫，就看到一張邀請卡（去做／等一下／今天算了）。回應不留紀錄，每天最多出現 2 次。**MVP 不做系統推播。**
- **替代**：本地通知（在家長手機上跳通知，孩子看不到，反而變成家長拿手機去催 → 違反 §2.7 的精神）；孩子自己的手錶／手機（多數 6–12 歲沒有）。
- **理由**：HANDOFF §4 把推播排除在 MVP 外；探頭模式不會在孩子沒開 App 時打擾，也不會變成家長的催促工具。之後若要做本地通知，只能做在「孩子自己的裝置」模式，並先過底線 3。

### B2 ✅ 低年級的書寫問題
- **選擇**：整個核心循環**不打字也能走完**：事情、時間點都是圖示 chip（家長範本＋孩子自己新增過的），「如果⋯我就⋯」用兩個槽拼出來；「為什麼」與歷程問題提供可點的短答案 chip（例如「我想試試看」「我自己想做」），自由輸入永遠是選項。**MVP 不做 App 內錄音**。
- **替代**：App 內語音輸入（兒童語音屬敏感個資，要上傳辨識服務，隱私代價高）、注音鍵盤教學（仍然慢）。
- **理由**：點選就能完成，6 歲也能自己走；孩子若用系統鍵盤的聽寫是 OS 功能，我們不錄音、不上傳音檔。chip 只提供「句子開頭／常見回答」，事情內容仍由孩子挑或自己寫（底線 6）。

### B3 ✅ LLM 的輸入來源
- **選擇**：只送 4 個欄位：孩子今晚對歷程問題的**原話**、當天第一件事的**事情名稱**、這件事的**回顧狀態**（做到／一部分／沒做）、**年齡語氣**（6–8／9–12）。不送名字、「為什麼」、心情、歷史紀錄。孩子沒說話（跳過或太短）→ **不呼叫 LLM**，直接用範本。LLM 必須回傳結構化結果：`learned`（步步的句子）＋ `source_quote`（孩子原話裡的一段），伺服器與 App 都檢查 `source_quote` 確實是孩子原話的子字串，對不上就退回範本。
- **替代**：連同計畫內容讓 LLM 自由推論（易編造）、送多天歷史讓它「更懂孩子」（資料最大化、違反 §2.8）。
- **理由**：「可回溯到原話」是防止編造最便宜也最可靠的檢查；事情名稱與狀態只用來讓語氣貼切（例如沒做的日子學「原來累的時候可以先休息」），不能變成學習內容的來源。

### B4 ✅ 家長端形式
- **選擇**：同一個 App 內的「家長區」，用家長自設的 4 位數 PIN 進入（第一次進入時設定）。家長區只有：事情範本、時間點範本、提醒時段、語氣年齡、LLM 開關、資料匯出／刪除，以及「孩子主動分享給你的內容」。
- **替代**：獨立家長 App、網頁後台（都需要帳號與雲端同步，MVP 範圍外）。
- **理由**：HANDOFF §5.4 建議；共用裝置的情境下最自然。PIN 不是資安機制，只是避免孩子誤入。

### B5 ✅ 年齡切換的時機
- **選擇**：兩者都可以——家長在初次設定時選一個預設；孩子在自己的「我的設定」裡可以隨時改「步步說話的方式」（標示為「說話方式：活潑／簡潔」，不標年齡）。
- **替代**：只由家長設（剝奪自主）、依生日自動切（多收一個個資、且孩子發展不等於年齡）。
- **理由**：分齡的本質是語氣與鷹架程度；用「說話方式」命名，讓 10 歲但喜歡活潑語氣的孩子也不會覺得被當小小孩。

## C. 產品與機制

### C1 ✅ MVP 先做哪個年齡組
- **選擇**：兩組共用同一個流程，差別只在文案語氣與預設鷹架（6–8 預設顯示更多 chip、句子更短）。文案庫的每一組句子都有通用版，必要時加 `[6-8]`/`[9-12]` 變體。
- **理由**：流程相同、只有語氣不同時，同時支援的成本很低；可以直接比較。

### C2 ✅ 心情暖身不存
- 心情選擇只存在當次畫面狀態，不寫入資料庫、不出現在匯出、家長端看不到。

### C3 ✅ 「步步學到」的引擎
- 範本引擎依（回顧狀態 × 孩子有沒有說話 × 語氣）抽句子，三種狀態的句子池一樣大；「沒做」那池的句子全部是「從孩子的選擇學到」的句型。
- LLM 模式：App 先在本機做危機偵測 → 沒事才送；逾時 3 秒時步步顯示「在想事情」，8 秒（🔁）退回範本；收到結果再過一次本機文案過濾＋回溯檢查，任一不過就退回範本。孩子看不出兩種模式的差別。
- 每天最多學 1 件；允許「今天沒什麼特別要記的」。

### C4 ✅ 學習筆記
- 孩子決定要不要「記進筆記本」；可加愛心標記、可選「給家長看」。筆記本依時間排列，不顯示數量、沒有目標、沒有進度條。

### C5 ✅ 成長軌跡的形式：「我的小路」
- 一條只由「有想計畫的日子」鋪成的小路，每天一塊石頭（上面是那天第一件事的圖示），沒想計畫的日子**不畫空格**。下方用文字說「你最常用的開始信號是⋯」「你常給自己排的事是⋯」，這個月想清楚的天數。不顯示完成率、不用「做到了」的狀態幫石頭上色。
- **理由**：只跟自己比，中斷不留疤；石頭的狀態不取決於完成度，免得變成另一種成績單。

### C6 ✅ 危機內容處理
- 本機關鍵詞＋句型偵測（自傷、受虐、嚴重困擾三類），在任何自由輸入送出時檢查；命中 → 步步切到預寫的安全回應（溫和、不驚嚇、引導找信任的大人，附台灣求助專線），**不呼叫 LLM、不把內容存進筆記本**。Cloud Function 端也有同一層檢查作為備援。
- ⏸ 偵測字表與安全回應文案需要兒童心理專業審核（參考文件亦如此要求）；文案庫提到「依安全機制通知家長」，但這和底線 7「家長看不到孩子沒分享的內容」有張力，MVP **不自動通知家長**，只鼓勵孩子自己去找大人——這一點是法規／兒少保護判斷，列給人決定。

### C7 ✅ 白天提醒與「今天算了」
- 三個選項回應後只有一句步步的話，不寫入資料庫，不影響回顧畫面，不通知家長。

### C8 ✅ 明確的結束
- 回顧完 → 「今天就到這裡囉」結束畫面；回到首頁後首頁進入「今天聊完了」狀態（步步放鬆），不再出現任何行動呼籲。

### C9 🔁 起始數字（`config.dart`）
- 每天最多 3 件事；提醒每天最多 2 次；步步一句話上限 60 字；LLM 重試 2 次；3 秒顯示思考、8 秒退回範本；筆記每天最多 1 則。

### C10 ✅ 視覺語言
- 不沿用原型的借來設計系統。暖色紙感底色、圓角、大觸控目標（≥ 48dp）、系統中文字型（iOS PingFang TC／Android Noto Sans CJK），不打包字型以控制體積。步步用 CustomPainter 畫，表情只有：開心、好奇、關心、平靜、驚訝、放鬆（沒有難過／生病／虛弱）。
- 「做到了／一部分／沒做」三個按鈕同尺寸、同字重、同底色，只用圖示（🌟🌗🌙）區分，不用紅綠。

## D. 實作（Foundation 之後補上）

### D1 ✅ 文案規則的格式與 L2 允許標記
- **選擇**：`shared/copy_rules.json` 分 `l1`（依類別）、`l2`、`concise` 三段，pattern 是 Dart 與 JS 都能吃的 regex；比對前先去掉空白。靜態文案要用 L2 詞，必須在同一行或上一行寫 `// copy-allow: <詞>`；LLM 與任何動態產生的步步句子一律拒絕 L2。
- **替代**：每句文案帶 metadata 欄位（較囉唆、lint 要解析建構子參數）。
- **理由**：註解標記讓 lint 用 analyzer 就能做到；顯式、好 grep、code review 看得到。

### D2 ✅ 匯出檔包含 outcome
- **選擇**：`exportJson()` 是完整匯出（含每件計畫的 outcome 與反思原話），但家長 PIN 不匯出。
- **替代**：匯出時拿掉 outcome。
- **理由**：底線 8 要求「可完整匯出」，這是資料可攜權，不是 App 內的家長檢視畫面；App 裡的家長區仍然只能讀 `ParentView`。匯出按鈕旁的說明文字會寫清楚檔案內容。

### D3 ✅ 共用裝置上的「一天」與重新計畫
- **選擇**：一天的 key 是裝置本地日期 `YYYY-MM-DD`。當天還沒回顧前可以重新計畫（覆蓋當天計畫）；昨天沒回顧的計畫不會被提起，也不影響今天（不讀「上次開啟」）。
- **理由**：底線 3、4：沒聊完的一天不留痕跡、不追問。

### D4 ✅ 探頭提醒的次數只記在記憶體
- **選擇**：每天最多 `AppConfig.maxPeeksPerDay` 次，計數只在記憶體（App 重開會歸零），回應不寫入資料庫。
- **理由**：C7 規定回應不留紀錄；為了「最多 2 次」而存一筆紀錄，等於開始記錄孩子的使用行為。重開歸零的代價只是偶爾多探頭一次。

### D5 ✅ 步步的名字 MVP 固定為「步步」
- **替代**：文案庫 4.1 的命名環節。
- **理由**：所有文案都要過 lint，名字變成變數會讓靜態檢查變複雜；先把核心循環做穩，命名列為下一步。

## E. Build 階段的決策（各模組）

### E1 ✅ 文案 lint 的範圍
- **選擇**：`tool/copy_lint.dart` 用 analyzer 掃 `lib/` 所有含中文的字串（含插值，`$x` 以 0 代入，所以「還有 $n 件」抓得到）。`Line` 第一個參數套活潑規則，第二個參數、`Line.same` 與 `Line` 以外的字串一律套簡潔規則（最嚴）。`lib/copy/` 以外出現中文字串就算違規，例外只有逐檔、逐字串的白名單（目前只剩 `models.dart` 的「如果⋯我就⋯」資料格式）。靜態文案不檢查 60 字；60 字只限制步步「生成」的話。
- **替代**：依目錄或 regex 放行（太鬆）；靜態文案也限 60 字（家長區說明會超過）。
- **理由**：同一份 `CopyRules` 在執行期與 lint 共用；白名單只會變少，不會變多（過期的項目 lint 會提醒刪掉）。

### E2 ✅ 護欄測試的掃描方式
- **選擇**：用 analyzer 的 token 掃識別字（註解自動排除）；禁用套件也掃 `pubspec.lock`（含間接依賴）；`bubu/` 只能透過 `bubu_inputs.dart` 拿裝扮、時鐘、亂數、語氣。
- **理由**：regex 去註解會誤判字串裡的 `//`；間接依賴一樣算 SDK。

### E3 ✅ 步步的動畫與表情
- **選擇**：`BubuView` 預設是靜態的；只有「在想」或明確 `breathe: true` 才有重複動畫，系統「減少動態」時也停。時段 enum 叫 `DayPart`（避開 Flutter 的 `TimeOfDay`）。未知的配件 id 一律退回 none／cream。回顧時對三種狀態的回應，步步的表情固定是「好奇」。
- **理由**：表情不隨 outcome 改變，才能保證三條路徑視覺權重相同（底線 2、4）；靜態預設讓所有畫面測試可以 `pumpAndSettle`。

### E4 ✅ 「步步學到」的範本引擎
- **選擇**：由「第一件計畫」的 outcome 決定句子池（與 LLM 只送第一件事一致）。三種 outcome 的池一樣大；「今天沒做」池全部是 `choice`。孩子有說話時先試引用原話的句子：引用一定是原話的子字串（整句 → 第一個放得下的子句 → 截短加⋯），整句要過 `passesGenerated`；孩子自己打了禁用詞（例如「我好棒」）就不引用。
- **替代**：多數決、挑「最有資訊量」的那件。
- **理由**：池等大、沒做也學得到，所以由哪一件決定都不會改變步步學到的份量。

### E5 ✅ LLM 的驗證與逾時
- **選擇**：App 與伺服器各驗一次：L1→L2→簡潔語氣→字數→`source_quote` 是原話的子字串→輸出沒有危機詞。App 端一個 8 秒總逾時涵蓋所有重試；伺服器 7 秒，比 App 早回 `{fallback:true}`。伺服器輸入嚴格只收 4 個 key（`childWords, task, outcome, tone`），多一個就拒絕；回應只有 `{learned, source_quote, kind?}`／`{safety:true}`／`{fallback:true, reason}` 三種。模型回 `plainDay` 時用我們預寫的平淡日句子，不用模型的字。log 只記次數與原因代碼，不記內容。
- **理由**：「可回溯到原話」是防編造最便宜的檢查；嚴格 schema 讓「最小傳輸」（底線 8）由伺服器強制，不靠 App 自律。

### E6 ✅ 危機偵測的正規化與安全畫面
- **選擇**：比對前做全形轉半形、小寫，去掉空白、標點、符號／emoji、零寬字元、注音聲調（App 與伺服器同一套，有共用 fixture `functions/test/crisis_samples.json`）。命中 → 全螢幕安全回應（步步「關心」、點名可以找的大人、台灣求助專線大字可複製、說明「你寫的字沒有被存起來」、只有一個「我知道了」）。回顧中命中：不存反思、不呼叫 LLM、仍記錄這天結束並道晚安。
- **理由**：孩子會插標點、空白、emoji；漏判的代價遠大於誤判（C6）。⏸ 字表與文案仍待專業審核。

### E7 ✅ 首頁與計畫流程

### E11 ✅ 平板版面

## F. 稽核後的修正（文案規則與危機偵測）

### F1 ✅ 生成句子的規則加寬，L1／L2 分界
- **選擇**：L1 新增：罪惡感／挽留（想你、想念、在等你、一直等、終於來、很久沒、幾天沒、都沒來、記得來、要回來、你去哪了⋯）；新組 `reminder_pressure`（下次記得、記得要、要記得、明天要、下次一定、應該要、別忘、不要忘）；新組 `pet_disappointment`（「我／步步（有點／好／很⋯）難過／傷心／失落」、遺憾、唉、偷懶）；讚美加超棒、棒棒、讚、很強／超強／真強、很乖／超乖（所有語氣）、`(好|很|真|超|太)(認真|用心|努力|勇敢|懂事|負責|有耐心)`、`(真|很|超|太)會`、`你好會`、`做得(真|很|超|好)?(好|不錯|棒)`（後面接累／辛苦⋯不算）、`不錯`（「不錯過」不算）；結果讚美加 `(都|全部)(做完|完成|做到)`。L2 新增 明天見、下次要、等你（靜態句「等你想好⋯」這種才合理，要 copy-allow；LLM 一律擋）。
- **替代**：照稽核原案把裸的「難過／傷心／失落」「會」「下次要」放進 L1；或只靠 prompt。
- **理由**：裸「難過」會擋掉步步重述孩子自己的感覺（「你說做之前很難過」），所以只擋步步自己難過；裸「會」會擋「你會先⋯」這種過程描述，所以只擋「很會／真會／你好會」。「你說你很乖」現在活潑語氣也擋（評價人，寧可退回範本）。規則擋下的代價只是退回範本句，所以邊界寧可嚴。
- 跟著改掉被新規則擋下的靜態句（改句子，不放寬規則）：「就會記得要做」→「就比較不會忘記」、「等你想好第一件小事」→「你想好第一件小事的那天」、「如果明天要再試一次」→「如果再試一次」、簡潔結尾「OK，明天見。」→「OK，今天就到這裡。掰掰。」（只說再見、不約明天，和活潑版一樣明確）。prompt 也補上「只用繁體中文」與新的禁用詞。

### F2 ✅ 比對前的正規化：App 與伺服器同一套
- **選擇**：文案規則與危機偵測共用一個正規化（Dart `lib/core/text_match.dart`、TS `functions/src/normalize.ts`）：寬度折疊（全形 → 半形、全形空白）→ 小寫 → 逐字簡轉繁 → 去掉空白、`\p{P}`、`\p{S}`、`\p{Cf}`、`\p{M}`、注音聲調與注音字母。字數仍用原文算。伺服器在寬度折疊前多跑一次完整 NFKC；Dart 沒有內建 NFKC，只做孩子會打到的那部分（寬度），兩邊在共用樣本上逐句一致。
- **簡體**：用對照表，不在 pattern 裡重寫一份簡體。表放在各自的 JSON（`simplifiedToTraditional`），只收「只會出現在簡體」的字（例如不收 后、几、系；這幾個用 pattern 的 `(幾|几)`、`(係|系)` 處理）。測試檢查表裡每個繁體字都被某個 pattern 用到、而且沒有 pattern 含簡體字（含了就永遠比不到）。
- **替代**：每個 pattern 都寫一份簡體（兩倍長、容易漏）；Dart 加 NFKC 套件（多一個依賴，只為了極少見的相容字元）。
- **理由**：「好～棒」「好​棒」「你好聪明」原本都過得了濾網；App 與伺服器各寫一套正規化就是 E6 那種漂移的來源。`app/test/guardrails/copy_parity_test.dart` 讀 `functions/test/parity_samples.json`，兩邊跑同一份樣本。

### F3 ✅ 危機偵測的正規化與伺服器一致
- **選擇**：Dart `CrisisDetector.normalize` 改用 F2 的正規化，連注音字母也去掉（原本只去聲調），和 `normalizeForCrisis` 一樣；`app/test/safety/crisis_parity_test.dart` 讀 `functions/test/crisis_samples.json`，每一句都要和伺服器判定相同。
- **理由**：原本「想ㄚ死」「我想ㄙ死」在 App 端漏判、只有伺服器抓得到；離線或 LLM 關閉時 App 是唯一一道檢查（底線 9）。E6 說「同一套、有共用 fixture」，現在由測試保證。

### F4 ⏸ 危機字表的注音與簡體變體
- **選擇**：每句比兩次：去掉注音字母的版本（抓「想ㄚ死」）與保留注音字母的版本（抓「我想ㄙˇ」這種用注音代替一個字）。含注音的 pattern 只會在第二次命中：`(想|去)ㄙ`、`ㄒㄧㄤㄙ`、`ㄙ(掉|了)算了`、`自ㄕ`、`ㄗㄕㄚ`、`不想ㄏㄨㄛ`、`跳ㄌㄡ`、`打ㄨㄛ`、`被ㄉㄚ`、`沒(有)?人ㄞ我`。單一聲母的 pattern 後面接 `(?![ㄅ-ㄩ])`，所以「我想ㄙㄨㄟˋ覺」「想ㄙㄢ點」不算。簡體（自杀、跳楼、没人爱我、活着好累⋯）靠 F2 的對照表。
- **替代**：只比去掉注音的版本（「我想ㄙˇ」會變成「我想」，漏判）；只比保留注音的版本（「想ㄚ死」漏判）。
- **理由**：6–8 歲常用注音代替不會寫的字；寧可誤判也不漏判（C6），但避開明顯的誤判。⏸ 新增的變體和原字表一樣，要等兒童心理專業審核。

### F5 ✅ 「今天沒做」的回應只有好奇
- **選擇**：拿掉「沒做就（是）沒做」與「是計畫的問題，還是那天的問題？」「那個時間點會不會有點難？」，改成「今天你都在做些什麼呀？」「原本排的那個時間點，你在做什麼呀？」；池仍是 4 句，兩種語氣都有。順手改：「貪心會累」→「排太多會趕」、簡潔版開心回應「不錯。」→「開心的早上。」、平淡日去掉結尾「這樣也不錯」。
- **替代**：只把「問題」換成「關係」（仍是在找原因）。
- **理由**：底線 4 要這一天完全中性；找原因預設了這天出了錯。「貪心」是給人的標籤（底線 5）；「不錯」是在打分數。`test/copy/audit_copy_test.dart` 鎖住這些改動。

### F6 ✅ 家長區 LLM 說明不替供應商做承諾
- **選擇**：說明改成我們自己做得到的事：只送孩子今晚的幾個字、當天一件事和語氣；伺服器只轉送、不留存、紀錄不寫內容；供應商的保留與訓練設定還在確認中（A3 尚待人決定）；另一行照舊說明目前只在開發用的模擬環境能用。
- **理由**：A3 還沒確認供應商端的設定，不能先寫「不保留、不訓練」給家長看（底線 8 的誠實面）。

## G. 稽核後的修正（App 行為與資料）

### G1 ✅ 首頁步步的表情只看時段（取代 C8「聊完了步步放鬆」、E7 的首頁表情）
- **選擇**：首頁表情改由 `lib/bubu` 的 `restingExpression(DateTime)` 決定（早上開心、白天與傍晚平靜、晚上放鬆），不再看「有沒有計畫」（原本有計畫才笑）與「聊完了沒」（原本聊完才放鬆）。唯一例外：探頭卡的問題正顯示、還沒回答時歪頭（對話中的反應）。計畫流程的心情／如果⋯／為什麼三步改用 `listeningExpression(answered:)`：還沒回答好奇、回答了一律「關心」，不分回答內容（心情的差別只留在步步說的話）。
- **替代**：固定一個表情；保留「聊完了 → 放鬆」並寫成例外；心情低落時才「關心」。
- **理由**：底線 2 寫的是外觀只因裝扮、時間、季節而變；「聊完了才放鬆」「排了計畫才笑」都是孩子做了什麼換來的表情，等於小小的酬賞（底線 1）。用時段的話，晚上每個孩子看到的都是放鬆的步步，C8 的「結束感」靠文字與沒有行動呼籲來給。

### G2 ✅ 表情呼叫點的護欄
- **選擇**：`test/guardrails/bubu_expression_callsite_test.dart` 用 analyzer 掃 `lib/features`、`lib/safety` 每一個 `expression:` 具名參數（BubuView 與 `_StepLayout`／`_SideBubu` 等包裝），識別字拆字後不得含 plan／outcome／lesson／record／ended／mood／done／review／cue／why／task 等；核可的 `restingExpression`、`listeningExpression` 整段略過，並另外檢查它們在 `lib/bubu` 的參數只有 `DateTime`／`bool`。允許清單目前是空的。附 fixture 自我測試。
- **替代**：只靠 code review；把所有表情選擇搬進 `lib/bubu` 的單一函式。
- **理由**：原本的護欄只掃 `lib/bubu`，而表情其實是在畫面裡挑的，首頁的「有計畫才笑」就這樣過了所有測試。

### G3 ✅ 刪除全部＝刪檔重開（實作 A4 原本的設計）
- **選擇**：開庫時 `PRAGMA secure_delete = ON`（`beforeOpen`）；`Repository.deleteAll` 刪完資料列後跑 `wal_checkpoint(TRUNCATE)` 與 `VACUUM`。裝置上另有 `DatabaseStore`：關閉資料庫、刪掉 `.sqlite` 與 `-wal`／`-shm`／`-journal`、在原位置開新庫並 seed，再 `ref.invalidate(databaseProvider)`（bootstrap 用 `overrideWith` 讓它每次拿 store 目前的庫），App 不用重開。家長區改呼叫 `deleteAllDataProvider`。測試用檔案型 NativeDatabase 讀原始位元組，確認孩子的句子不在磁碟上。
- **替代**：只做 secure_delete＋VACUUM（不刪檔）；請家長重開 App。
- **理由**：底線 8 的「可完整刪除」要連 SQLite 的空閒頁面一起清；兩層都做，測試環境（in-memory）也有同樣保證。

### G4 ✅ 不進系統雲端備份
- **選擇**：Android `<application android:allowBackup="false" android:fullBackupContent="false" android:dataExtractionRules="@xml/data_extraction_rules">`，規則檔在 cloud-backup 與 device-transfer 都排除所有 domain。iOS：資料庫改放 `Library/Application Support`（`getApplicationSupportDirectory`，原本是 Documents），AppDelegate 啟動時對整個資料夾設 `isExcludedFromBackup = true`。`test/guardrails/no_cloud_backup_test.dart` 檢查 manifest、規則檔與 AppDelegate。
- **替代**：用 platform channel 只標資料庫檔（但 -wal／-journal 會一直重建）；只在說明裡告知家長。
- **理由**：備份會把孩子的原話帶出裝置，刪除全部也刪不到雲端副本，重裝還會還原（底線 8）。⏸ iOS 的排除要在實機確認（設定 → iCloud → 備份看不到這個 App 的資料）。MVP 尚未發佈，所以舊位置（Documents）不做搬移。

### G5 ✅ 伺服器端攔下危機訊號時走同一條安全路徑
- **選擇**：回顧的反思改成「步步學到」回來、確定不是 safety 結果後才存。若結果是 `LessonSource.safety`（只有伺服器抓到），清掉這一天的反思（`saveReflection(day, null)`），顯示 `SafetyResponseScreen`（通用版、含專線），孩子關掉後道晚安並結束這一天，和本機攔下完全一樣。
- **替代**：先存再刪（文字會短暫寫進磁碟／WAL）；只顯示一句卡片（原本的做法）。
- **理由**：底線 9 與 C6 的「不存、給預寫的安全回應」不能因為是哪一層抓到而不同。

### G6 ✅ 探頭卡在輸入改變時重新決定（修正 E7「每次進首頁只決定一次」）
- **選擇**：首頁在這幾個時候重新決定一次：第一次載入、今天的計畫從無到有、App 從背景回來（`WidgetsBindingObserver`，同時重算今天的 dayKey）、從別的畫面 pop 回首頁。仍受記憶體裡的每日上限（`AppConfig.maxPeeksPerDay`）限制、每次最多一張；卡片正顯示且還沒回答時回到前景，不重抽也不多算。
- **替代**：計時器每分鐘檢查；本機通知。
- **理由**：App 通常留在背景而不是被關掉，原本「每個 State 只決定一次」讓家長設的提醒時段幾乎永遠不出現。沒有計時器、沒有推播，壓力不會變多（底線 3）。

### G7 ✅ 家長與孩子範本的去重分開算
- **選擇**：`addTaskTemplate`／`addCueTemplate` 只和「呼叫者看得到的來源」比：家長／預設只和家長／預設比，孩子可以重複使用任何來源。孩子挑選清單（`watchTaskChoices`／`watchCueChoices`）同一句只列一次，優先家長那筆（保留「爸媽建議」）；匯出仍含全部列。
- **替代**：家長新增時提示「已經有了」（一樣會洩漏）；DB 加 unique(label)。
- **理由**：原本家長新增孩子寫過的句子會「新增了卻沒出現」，家長能用猜的確認孩子的私人事情庫（底線 7）。

### G8 ✅ debug 建置允許連本機 emulator 的 HTTP
- **選擇**：只在 `android/app/src/debug/` 加 `network_security_config`，允許 10.0.2.2、localhost、127.0.0.1 的明文 HTTP；main（release）不變。
- **替代**：在 main manifest 開 `usesCleartextTraffic`。
- **理由**：Firebase emulator 只提供 HTTP，Android 9+ 預設擋明文，LLM 模式會一直默默退回範本。正式版不需要也不應該允許明文。

### G9 ✅ 從背景回來時重抽問候
- **選擇**：首頁 `resumed` 時清掉快取的問候，下次 build 依現在的時段重抽；從別的畫面回首頁不重抽。
- **理由**：早上打開、晚上才回來時還在說早安。問候只吃（語氣、時間、亂數），沒有碰到底線 2。

### G10 ✅ 前景跨過午夜時自己換天；回顧中途不換
- **選擇**：`todayKeyProvider` 在系統時鐘下排一個「下個午夜＋1 秒」的計時器，到時 `invalidateSelf`；`FixedClock`（測試）不排。回顧在 `start()` 時把日期定下來，聊到一半跨過午夜仍寫回同一天。
- **替代**：只靠首頁的 `resumed`（前景跨夜會一直停在昨天）；每分鐘輪詢（多餘的喚醒）。
- **理由**：前景跨夜後新的計畫不能寫到昨天；但 23:59 開始的回顧，計畫不應該在中途消失。

### G11 ✅ emulator 模式的 Firebase 專案 ID 預設 `demo-little-steps`
- **選擇**：`FIREBASE_PROJECT_ID` 預設改成 `demo-little-steps`，和 README 的 `emulators:start --project` 一致。
- **理由**：專案 ID 不一樣時 Functions SDK 會打到別的路徑，呼叫失敗、默默退回範本。這個 client 只在 emulator 模式下建立，`demo-` 專案也保證碰不到真的雲端資源（呼應「不准部署」）。

## H. 第一階段收尾：2026-11-06 稽核的兩個 bug

### H1 ✅ 探頭卡看「輸入」有沒有變，而不是只看第一次載入
- **問題**：家長在家長區新增一個涵蓋現在的提醒時段，回首頁後步步不探頭，要再進出別的畫面才出現。回到首頁的第一個 frame 拿到的還是舊設定（首頁被蓋住時它的訂閱是暫停的），探頭就用舊設定決定了「不探」，新設定到了也不再決定。
- **選擇**：首頁記下上一次決定時的輸入（提醒時段的起訖、今天有沒有計畫、聊完了沒）。輸入一變、而且這次還沒探頭過，就重新決定一次；仍受每天上限與「一次進來最多一張」限制。取代原本只看「計畫從無到有」的特例（G6）。
- **替代**：回首頁時延遲一下再決定（猜時間，不可靠）；家長區存檔時直接通知首頁（家長區多了一條通往孩子畫面的線）。
- **理由**：不管設定什麼時候到，結果都和「重新打開首頁」一樣；只讀設定，不多記任何東西。

### H2 ✅ 刪除全部資料＝先收掉整個 App，再刪檔重開，再從首頁重建
- **問題**：刪除全部資料後，孩子端（首頁、筆記本、小路）還是舊的說話方式、裝扮、「今天聊完了」，要重開 App 才恢復。在 Linux 桌面版用真的資料庫檔追到原因：資料列刪完之後，`DatabaseStore.reset()` 要關掉資料庫，但被家長區蓋住、暫停中的首頁還掛著查詢訂閱，關資料庫一直等不完，後面的「開新檔＋換 provider」永遠沒跑到。資料其實已經刪了（所以重開就好），只是畫面一直停在舊資料庫最後送出的值。另外刪完之後家長區 widget 已被拆掉，還用它的 `ref` 會丟例外。
- **選擇**：App 最外層改成 `AppRoot`（`ProviderScope` ＋ `LittleStepsApp`，可以「重新開始」）。刪除全部：先刪資料列（secure_delete＋VACUUM）→ `AppRoot` 收掉整個 ProviderScope 與畫面堆疊（訂閱全部取消）→ 這時才關檔、刪檔、開新檔 → 用同一份啟動設定重建，回到剛安裝的首頁。家長區刪完之後不再碰自己的 `ref`／`context`。
- **替代**：一個一個找出暫停的 provider 手動 invalidate（脆弱，下次新增 provider 又會漏）；只刪資料列不換檔（不符 G3／底線 8 的「刪檔」）；請家長自己重開 App（體驗差，也容易以為沒刪乾淨）。
- **理由**：結果和重開 App 一樣乾淨，而且不依賴 Riverpod 暫停訂閱的細節。刪除後家長區自然關上（PIN 也一起刪了），回到首頁正好是「剛安裝」該有的樣子。`integration_test/parent_round_trip_test.dart` 在裝置（或 Linux 桌面版）上用真的磁碟與背景 isolate 驗這兩個 bug；`test/flow/parent_round_trip_test.dart` 用 widget test 驗同一條路徑。

### H3 ✅ README 已知問題 1–3（2026-11-06 截圖時看到的）
- **探頭時間點**：探頭卡原本永遠提第一件事和它的時間點，早上也會問「你說吃完晚飯要⋯，現在方便嗎？」。現在用 `pickPeek(now, plans)` 挑：先找時間點落在現在的那一件；再找看不出時段的時間點（「我喝完水」、孩子自己寫的，隨時都可能）；都對不上就提第一件、換成不帶時間點的句子（「你說今天要⋯，現在方便嗎？」）。時間點落在一天哪一段，用 `PlanCopy.cueHints*` 的關鍵字（早餐、放學、晚飯、澡⋯）比對，時段範圍在 `CueTimeConfig`。
  - **替代**：時段和時間點直接綁定（家長設時段時選對應的時間點；孩子自己寫的時間點對不上，而且家長端要多一層設定）；探頭只說事情不說時間點（丟掉「如果⋯我就⋯」的提示作用，B1 本來就是要提醒時間點）。
  - **理由**：關鍵字比對只影響「要不要帶時間點」，猜錯的後果是少說幾個字，不會問錯時間；不需要新的資料或設定。
- **問候**：早上與白天的問候池各有一句「今天想做／安排什麼呀？」，有計畫後首頁仍可能抽到。問候依規定不能讀計畫（步步只吃裝扮、日期、隨機），所以不是加判斷，而是把這兩句換成步步自己的事（伸懶腰、看雲），並加測試鎖住問候池不能問今天要做什麼。
- **筆記本引用兩次**：範本句子帶了孩子原話（「你說『先整理桌子』⋯」）時，筆記頁下面又多一行「你說：「先整理桌子」」。現在句子已經含原話就不再另寫一行；LLM 的句子沒引用時照舊另寫。

## I. 第二階段：家長同行＋分齡

### I1 ✅ 話術轉譯器與每週一則：靜態內容，不讀孩子任何資料
- **選擇**：家長區多一個「陪伴小工具」區塊，兩個入口都推在家長區自己的 Navigator 上（仍在 PIN 後面、沒有網址）。**話術轉譯器**：家長自己點一個情境（排的事沒有動／想放棄／我想建議一件事／孩子做到了／不想排計畫），顯示「別這樣說 → 先接住感受 → 給一個選擇 → 說出理由 → 為什麼」。**每週一則**：六則各約兩分鐘（結構≠控制、誇做法、心理控制、給理由、陪不是替、我們家一起），依日期每週一換，這週的放最上面，其他週的照順序往下排。
- **替代**：依孩子當天的回顧自動推薦情境（等於把孩子有沒有做告訴家長，違反底線 7）；用 LLM 即時改寫家長的話（要把家長與孩子的對話內容送出去，且難以保證過文案規則）；記錄家長讀過哪幾則再推下一則（多記一筆使用紀錄，沒有必要）。
- **理由**：§9.4 的 ⚠️ 是「不能讓家長看到孩子實際有沒有做」——情境由家長自己選，這個功能從程式上就拿不到孩子的資料（測試鎖住 `parent_guide.dart` 不讀 repository／ParentView／settings）。「別這樣說」的例子也要過文案規則，所以不直接引用評價人的誇獎，改成描述那種說法。

### I2 ✅ 全家一起：家人的「今天的我」＋家人留言由步步轉達
- **選擇**：資料庫升到 v2，多兩張表（`family_today_entries`、`family_notes`）。家長區「全家一起」可以：寫自己今天想做的一件事（一位家人一天一件，同一人再寫就覆蓋）；留一句話給孩子。孩子的首頁：列出「家人今天想做的事」（只列出，不計數、不比較、沒有做到了沒）；有留言時出現「某某有留話給你喔，要看嗎？」（看看／等一下，份量相同），打開後**原封不動**顯示，步步不加評論（文案庫 §4.11）。孩子在「我的設定」可以關掉轉達。
- **家長的字要過文案規則**：留言與「今天的我」用和 LLM 輸出一樣嚴的檢查（L1、L2、幼稚詞全擋），不過就留在對話框裡說明被擋的詞——步步只轉達鼓勵，不轉達評價、催促、罪惡感。
- **沒有已讀回條**：`childRead` 只用來決定首頁要不要再轉達；`ParentView` 沒有這個欄位，也看不到孩子有沒有關掉轉達（護欄測試鎖住 key 與值）。「等一下」只記在記憶體。
- **替代**：家長留言直接推播到孩子裝置（範圍外，也違反 B1）；讓孩子回覆家長（會變成家長追問的管道，先不做）；顯示「今天你們家有三個人想好了」（文案庫 §4.12 的例句，但孩子沒排的日子就變成壓力，不做計數）。
- **理由**：企劃書 §9.5 的關聯（relatedness）是華人脈絡下保護自主感的關鍵；但這個功能最容易變成「家長透過步步催孩子」，所以在寫入端擋文字、在讀取端拿掉已讀。月回顧裡的「我們家的成長回顧」放到第三階段月回顧一起做。

### I3 ✅ 完整分齡：兩種說話方式在流程上也不一樣
- **選擇**：仍是 B5 的兩種「說話方式」（活潑≈小樹苗 6–8、簡潔≈小探險家 9–12），畫面上不標年齡、孩子隨時可以換；但現在差別不只語氣：
  - **活潑**：孩子的畫面字放大 1.12 倍（疊在系統字級上，家長區不放大）；時間點、為什麼、回顧短答案前面都有小圖示；選到 2 件時軟性提一句「兩件就很夠了，想再加也可以」（硬性上限仍是 3）；回顧的歷程問題短答案在前，寫字要自己點開。
  - **簡潔**：每件事在「為什麼」之後多一步可跳過的「卡住的話，我就⋯」（MCII／企劃書模組二的障礙計畫），選項是下一步怎麼做（先做一分鐘、深呼吸、換順序、休息五分鐘、找人問），也可以自己寫（過危機偵測）；存進計畫（資料庫 v3 加 `stuck_plan` 欄），確認頁與首頁計畫卡多一行；回顧的歷程問題一開始就有寫字的框。
  - 「我的設定」每個選項多一行說明兩種方式的差別。
- **替代**：用年齡或年級切換（B5 已排除）；小樹苗硬性只能選 2 件（企劃書寫的是「建議」，硬擋會剝奪選擇）；注音標註（需要打包注音字型或 ruby 排版，Flutter 沒有現成的方案，先不做，列為待辦）。
- **理由**：企劃書 §10 的分齡是鷹架程度不同，不是只換語氣。「卡住的時候」放在 9–12 是因為後設認知上升、能預想障礙；6–8 用圖示與大字降低讀寫負擔。所有選項都只是提問與選項，內容仍由孩子決定（底線 6）。

### I4 ✅ 家長建議的事用另一個顏色，孩子選了就變自己的顏色
- **選擇**：排計畫「選 1–3 件事」裡，家長建議、孩子還沒選的事是淡藍底＋藍邊（`AppColors.suggestSoft`／`suggestLine`）；孩子一選，就和其他自己選的事一模一樣（同樣的選取色、同樣的邊）。取消選取就回到淡藍。之後的「如果⋯我就⋯」、確認頁、首頁、回顧都不標來源（`Plan` 本來就不存 origin）。
- **替代**：選了以後仍保留「家長建議」的小標記（等於永遠記得是誰出的主意，和「內化」相反）；用更亮、更搶眼的顏色（會變成暗示孩子該選，違反底線 6）；在家長端顯示孩子選了哪些建議（底線 7）。
- **理由**：企劃書模組一「家長建議的項目以不同顏色標示，孩子選了就變成自己的顏色（視覺化內化的過程）」。顏色只比一般選項淡、不比它重，區塊標題仍是「家長的建議，可以不選」。

### I5 ✅ 計畫品質提示（MCII）：太模糊時步步只問一句
- **選擇**：「如果⋯我就⋯」選好時間點之後，看事情和時間點有沒有太模糊，一次只問一件：
  - 事情是「不要⋯」（`negativeTaskWords`）→「不做那件事的時候，你想改做什麼呢？」
  - 事情沒有看得見的終點（認真、努力、好好、多一點⋯，`vagueTaskWords`）→「這件事做到什麼樣子，就算做完了呢？」
  - 時間點不是一件事（有空、等一下、想到⋯，`vagueCueWords`）→「那大概是什麼時候呀？是哪件事做完的時候呢？」
  問題放在步步的對話泡泡，下面兩顆一樣大的按鈕：「改一下」打開孩子自己的輸入框（從孩子原本的字開始，不幫忙填）；「這樣就好」就不再問同一句。提示不擋「下一步」，不存、不給家長看。內建的事情與時間點都不會觸發（測試鎖住）。
- **替代**：直接給改寫好的句子讓孩子選（代寫計畫，底線 6）；用 LLM 判斷模糊度（多送資料、又要處理失敗；關鍵字已能抓到最常見的三種）；擋住下一步直到改好（變成要求，不是提問）；每件事都問（太煩，而且多數計畫沒問題）。
- **理由**：企劃書與 MCII 研究（Oettingen、Gollwitzer）都指出：時間點要是具體情境、行動要具體，「不要做 X」改成「改做 Y」較有效。只問一句、可以略過，計畫仍然是孩子自己的。

## J. 第三階段：探索角、驚喜盒、成長軌跡、月回顧

### J1 ✅ 探索角：每日一個小疑問＋塗鴉牆，不記錄、不評分
- **選擇**：首頁安靜導覽多一個「探索角」。**每日一個小疑問**：二十題都跟「怎麼長大、怎麼學會」有關（睡眠與記憶、跌倒十幾次才學會走、年輪窄的那年也算一年、休息時肌肉變強、習慣要兩個多月且漏一天沒影響、說出感覺的名字⋯），先給一半，點「點開看」才出現另一半（Loewenstein 的資訊缺口）；依日期每天換一題，「換一題」只在記憶體。沒有選項、沒有對錯。**塗鴉牆**：手指畫、六個顏色、擦乾淨、「送給步步」，步步只說收到、謝謝或問「你畫的時候在想什麼」，不評價畫得怎樣；畫不存，離開就清空（畫面上直接說）。
- **替代**：猜答案的選擇題（會出現「答對了／答錯了」，變成考試）；記錄看過幾題、做出收集冊（變成收集進度，接近底線 1）；把畫存起來貼在步步房間（要多一張表、匯出與刪除都要跟著改，先不做，等真的有孩子想留再說）；一般冷知識（企劃書的內生性檢核：跟成長主題無關的就是誘人細節）。
- **理由**：探索角的價值在「這個 App 本身有好玩的理由」，但不能跟做了什麼掛勾。測試鎖住 `lib/features/explore/` 不讀 repository／計畫／回顧／筆記的 provider、不 import 資料層，並確認畫畫、送給步步之後匯出的資料完全沒變。

### J2 ✅ 驚喜盒＋輕點步步：依日期不定期出現，不是任何事的獎勵
- **選擇**：探索角大約三分之一的日子會多一個盒子（`surpriseBoxOn(DateTime)` 以日期當亂數種子，同一天結果一樣、不固定在星期幾），打開是一句步步自己的小故事（用左手畫樹、把襪子穿反⋯）加一個表情，可以「再搖一下」。沒有盒子的日子什麼都不顯示，不說「今天沒有」。首頁輕點步步會嚇一跳、說一句小話，約兩秒後回到原樣（隱藏互動，不提示、不記錄）。
- **替代**：做完計畫或回顧後才出現盒子（就是「完成 N 件解鎖 X」，底線 1）；連續幾天打開有額外內容（streak）；把開過的故事收集起來（收集進度）；盒子在首頁出現小紅點提醒（首頁沒有任何徽章）。
- **理由**：Deci 等人（1999）的邊界條件是「非預期、非任務綁定」的驚喜不侵蝕動機。邏輯放在 `lib/bubu/surprise.dart`，自動受 bubu 的 import 邊界約束；護欄測試鎖住簽名只能是 `surpriseBoxOn(DateTime)`、`pickSurprise(Random)`，並確認打開盒子後匯出的資料沒變。故事都是步步自己的事，不問孩子做了沒、不評價。

### J3 ✅ 成長軌跡多兩種樣子：一棵樹、星空（孩子自己選）
- **選擇**：「我的小路」上方多一排「小路／一棵樹／星空」，孩子點了就換，存在孩子的設定（`trailStyle`，有匯出、家長端看不到）。**一棵樹**：有計畫的日子一片葉子，排在蜂巢格上、照時間從樹冠中間往外長（最早的在中間），樹冠碰到兩邊就往上長；樹不會掉葉、不會變色。**星空**：一天一顆星，照日期蛇行排列，用細線連成一個不斷的大星座，新的在上面。每片葉子／每顆星都長得一樣（只有那天第一件事的圖示，長按看日期），測試鎖住做到了、做了一點、今天沒做三種結果下外觀完全相同。
- **替代**：用日曆排（沒排的日子會變成空格，HANDOFF 明講不行）；樹在沒排的日子掉葉、星星熄滅（底線 2、3）；葉子大小或星星亮度依完成度（底線 4）；把空著的位置先畫出來等孩子填滿（變成「還差幾格」）。
- **理由**：HANDOFF 的條件是「沒做的日子不顯示成斷點或空洞」——資料來源仍是沒有 outcome 的 `plannedDays`，三種樣子都只是把同一串日子換個排法。讓孩子選樣子是企劃書模組五「設計自己的成長地圖樣式」，屬於自主支持。

### J4 ✅ 月回顧「這個月的我」：用故事說，親子各寫一句
- **選擇**：小路頁右上多一個「這個月的我」，打開是一本成長故事書，一個月一頁（新的在前，可以往前翻）：步步用幾句話說這個月——自己想清楚了幾天要做什麼、最常排的事、常在什麼時候開始，最後一句「這些都是你自己排的」；沒排過事的月份只說「想排的時候再排就好」。下面列出這個月家人寫過的「今天的我」（同一件只列一次，不計數）。**這個月的信**：孩子可以寫一句給家人（先過危機偵測，命中就走安全回應、不存），畫面直接說「家人在家長區看得到這一句」；家人在家長區「全家一起」寫一句給孩子（和留言一樣過文案規則），原封不動夾進孩子那一頁。一個月每人一封，再寫就覆蓋，只有這個月能寫或改，以前的月份只翻閱。資料庫升到 v4（`month_letters`），有匯出、刪除全部會一起刪。
- **ParentView 只多「信」**：`monthLetters` 每個月只有 `month`、孩子寫了才有的 `child`、家人自己的 `parent`；故事裡的天數、最常排的事都不在家長端（護欄測試鎖住 key 白名單與內容）。
- **替代**：月報表（完成率、和上個月比，底線 4、7）；把孩子的故事頁也給家長看（孩子沒主動分享的內容，底線 7）；文案庫 §4.10 的「這個月你換過三次計畫方式」（要多記一個計數，先不做）；原型裡的「沒寫的日子，路還在那裡等你」（「等你」是挽留語氣，底線 3）。
- **理由**：企劃書模組七與原型都強調「敘事而不是數據」。孩子寫給家人的那一句本身就是孩子主動的分享動作，所以家長看得到；孩子的回顧內容與故事數字仍然只屬於孩子。

## K. 驗證

### K1 ✅ 各情境 E2E：一份情境、兩種跑法
- **選擇**：`app/integration_test/scenarios/` 七組、24 個情境，全部從畫面點（資料庫只拿來檢查結果），跨日用「App 進背景 → 時間往前 → 回到前景」模擬（和真的隔天打開走同一條路：首頁 invalidate 今天、重抽問候、重新決定探頭）。共用驅動器 `integration_test/e2e/harness.dart` 依執行環境分流：在裝置／桌面上（`tool/e2e.sh <device>`）用 App 真正的啟動方式——磁碟資料庫、AppRoot 的刪檔重開，每個情境開始與結束都把裝置上的資料庫刪掉重開；在 `flutter test`（`test/e2e/`）換成 in-memory 資料庫，CI 每次都跑。分享面板換成記下內容的函式；亂數固定種子。
- **替代**：只在裝置上跑（CI 沒有裝置，情境很快就會壞掉沒人發現）；用 repository 直接塞資料再截圖（不是從孩子或家長的手走過一遍，H1 那種「回到首頁看到舊資料」的 bug 抓不到）；Patrol／Appium 之類的外部驅動（多一套工具與權限，Flutter 自己的 integration_test 已經夠用）。
- **理由**：HANDOFF §4 的驗收是行為，不是單一畫面；2026-11-06 稽核的兩個 bug 都是跨畫面才出現。情境檔用人看得懂的步驟寫，裡面的檢查也順便鎖住底線（家長端看不到沒分享的內容、心情不存、危機內容不存、驚喜盒與探索角不寫資料、軌跡記號長得一樣）。
- **沒驗到的**：真機（iOS／Android，雲端沒有裝置）、LLM 模式（Firebase 外掛不支援 Linux，也沒有部署）、平台分享面板、真的推播（App 本來就沒有推播）。這幾項要在本機用 `tool/e2e.sh <手機 id>` 與 README 的實機驗證步驟補。
