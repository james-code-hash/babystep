## 一、結論摘要

### ✅ 「寵物向孩子學習」——強烈建議採納

這個機制有紮實的實證基礎（徒弟效應），且**同時滿足 SDT 三項需求**，是目前為止所有功能提案中理論契合度最高的一個。

它還解決了一個既有的產品缺口：**孩子需要一個「向家長分享」的自然理由**。「我今天跟步步說了⋯然後牠學到⋯」比「我今天完成了 3 項任務」更容易開口，也更不像成績報告。

### ⚠️ LLM 導入——建議採納，但必須採混合架構

LLM 能實現「真實的、具體的、非罐頭式的學習回應」，這是範本文案做不到的。但 LLM 有**五項風險直接牴觸本產品的核心原則**，其中最嚴重的是：

> **LLM 的預設行為就是諂媚（sycophancy）。它會自然而然地說「哇你好棒！你好聰明！」——這正是本產品第十二章明令禁止的能力讚美（Mueller & Dweck, 1998：能力讚美導致失敗後低堅持、低享受、差表現）。**

這不是調整 prompt 就能完全解決的傾向，需要**架構層級的三重防護**（詳見第六章）。

### 🚫 一條新增的紅線

> **步步必須在孩子「什麼都沒做」的日子，也能從孩子身上學到東西。**
>
> 若步步只在孩子完成任務時才「學到」，「學習」就退化成一種新的酬賞——孩子會為了讓步步學到而做事，過度辯證效應照樣成立。這是整個機制成敗的關鍵。

## 二、實證基礎：徒弟效應

### 2.1 什麼是徒弟效應（Protégé Effect）

人們為了**教別人**而學習時，投入的努力高於為自己而學。這個效應在教學代理人領域有直接驗證。

**核心研究：Chase, Chin, Oppezzo & Schwartz (2009), *Journal of Science Education and Technology* 18: 334–352**
「Teachable Agents and the Protégé Effect: Increasing the Effort Towards Learning」

- 使用 Vanderbilt 大學 Biswas 團隊開發的 **Betty's Brain** 系統——學生「教」一個名叫 Betty 的虛擬代理人
- 發現：教代理人的學生**花更多時間學習、投入更多努力**，且效果優於為自己學習的對照組
- 研究者提出兩個機制：
  1. **自我保護緩衝（ego-protective buffer）**：失敗歸因於代理人而非自己，降低了失敗的威脅感，反而更願意持續嘗試
  2. **社會責任感（social responsibility）**：對「學生」產生責任感，提升投入

### 2.2 相關文獻支持

| 研究 | 發現 |
|---|---|
| **Bargh & Schul (1980)** | 「預期要教別人」本身就改變學習方式與深度 |
| **Roscoe & Chi (2007), *Review of Educational Research*** | 導生學習（tutor learning）的效益來自「反思性知識建構」——解釋的過程本身促進理解 |
| **Fiorella & Mayer (2013, 2014), *Contemporary Educational Psychology*** | 「為教而學」與「實際教學」皆提升理解與保留；實際教學效果更持久 |
| **Biswas, Leelawong, Schwartz & Vye** (Betty's Brain 系列) | 教學代理人促進後設認知與自我調節 |
| **Okita & Schwartz (2013)** | 觀察自己教出來的代理人表現，能促進反思學習 |

### 2.3 為什麼對 6–12 歲特別有效

- 這個年齡層很少有「當老師」的機會——他們永遠是被教的一方
- **「我知道一些別人不知道的事」是這個階段極少被滿足的勝任感來源**
- 教學代理人研究一致顯示：**對 K-12 學生的效果優於大學生**（Schroeder, Adesope & Gilbert, 2013，43 研究、N=3,088）

## 三、為什麼這個機制特別適合本產品

### 3.1 一次滿足 SDT 三項需求

| 需求 | 如何被滿足 |
|---|---|
| **勝任 Competence** | 「我懂一些步步不懂的事」——這是最直接的勝任感來源，且**不依賴任何外部評價** |
| **自主 Autonomy** | 孩子決定要告訴步步什麼、教牠什麼。這是完全由孩子主導的資訊流向 |
| **連結 Relatedness** | 教學關係本身就是一種深度連結；孩子從「被陪伴者」變成「給予者」 |

> **關鍵洞察：這是產品中唯一一個「孩子是給予方」的環節。**
> 在其他所有環節，孩子都是接受提醒、接受回饋、接受陪伴。這個機制把關係反轉過來——**而反轉恰恰是勝任感的來源。**

### 3.2 解決了「分享慾」的設計難題

原本的設計中，孩子向家長分享的內容是「我今天做了什麼」——這在華人家庭很容易被接收成「進度回報」，家長的自然反應是評價。

改成「步步今天跟我學到⋯」之後：
- 話題從**成果**轉向**過程與想法**
- 孩子是**故事的敘述者**，不是被檢查的對象
- 家長更容易做出好奇性回應，而非評價性回應

### 3.3 強化「功勞歸還孩子」原則

企劃書的原則四要求「把功勞還給孩子」。「步步從你身上學到」是這條原則最強的實現形式——**功勞不只歸還，還被明確地記錄下來。**

## 四、最關鍵的設計陷阱

### 🚫 陷阱一：讓「學習」變成新的酬賞（最嚴重）

**錯誤設計：**
```
孩子完成任務 → 步步學到新東西 → 步步變聰明／升級
孩子沒完成 → 步步沒學到 → 步步停滯
```

這在心理機制上**與集點系統完全相同**。孩子會為了「讓步步學到」而做事，這正是過度辯證效應（Deci, Koestner & Ryan, 1999，完成綁定酬賞 d = −0.36）。

**正確設計：**
```
孩子分享任何事 → 步步學到東西
（包括「今天沒做，因為我很累」→ 步步學到「原來累的時候需要休息」）
```

> **硬性規則：步步在孩子「什麼都沒做」的日子，也必須能學到東西。**
> 因為步步學的不是「怎麼完成任務」，而是**「這個人是怎麼想事情的」**。

---

### 🚫 陷阱二：假裝學習（真實性崩壞）

**風險：** 如果步步說「我學到了！」但內容空泛、明顯是罐頭句，9–12 歲的孩子會立刻察覺造假，整個角色的信任度崩塌。

> 依據：9–12 歲兒童的泛靈思維減弱、懷疑能力上升。低年級可能接受，高年級不會。

**對策：**
- 步步學到的必須是**具體的、可回溯到孩子原話的內容**
- 學得少沒關係，但**不能編造**
- 孩子只說了一句話，步步就只學一件小事

**對照範例：**

| ❌ 假裝學習 | ✅ 真實學習 |
|---|---|
| 「哇！我學到好多東西！」 | 「你剛剛說『先寫最討厭的』——這個順序我沒想過。」 |
| 「你教會我要努力！」 | 「原來卡住的時候可以先跳過。我以前都想說要按順序。」 |
| 「跟你在一起我變聰明了！」 | 「你說你累的時候會先躺五分鐘再起來。五分鐘欸，很短。」 |

---

### 🚫 陷阱三：把「教學」變成義務

**風險：** 若 App 要求孩子「今天要教步步一件事才能結束」，教學就從自主行為變成任務——自主需求被挫敗。

**對策：**
- 分享永遠是**可跳過**的
- 步步不會要求、不會期待、不會提醒「你今天還沒教我」
- 孩子不說，步步就從**孩子的選擇本身**學（「今天你選了先休息，我記下來了」）

---

### 🚫 陷阱四：步步變得比孩子聰明

**風險：** 若 LLM 讓步步展現出成人級的知識與表達，「我從你身上學到」就變成明顯的哄騙，勝任感崩塌。

**對策：**
- **步步的知識水平必須設定為略低於同齡孩子**
- 步步可以不懂常識、可以問笨問題
- 步步的表達要簡單、偶爾詞不達意
- **這是 LLM 最需要被「限制」而非「發揮」的地方**

## 五、機制設計規格

### 5.1 觸發時機

在夜晚回顧環節（企劃書 §5.2 ③）的**歷程問題之後**、結束語之前。

```
孩子勾選今天做了什麼
        ↓
步步問一個歷程問題
        ↓
孩子回答（可跳過）
        ↓
【新增】步步說出牠學到的事  ← 本機制
        ↓
（可選）孩子決定要不要分享給家長
        ↓
結束
```

### 5.2 步步可以學什麼（四類）

| 類別 | 說明 | 範例 |
|---|---|---|
| **① 方法** | 孩子用的策略、順序、技巧 | 「先寫最討厭的那一項」 |
| **② 自我認識** | 孩子對自己的觀察 | 「我早上比較有精神」 |
| **③ 感受** | 孩子的情緒經驗 | 「卡住的時候會想放棄，但過一下就好了」 |
| **④ 世界的事** | 孩子知道而步步不知道的知識 | 「原來直笛的高音要按半孔」 |

> **注意：四類中只有第一類與「完成任務」相關。** 這確保了在沒做事的日子，步步依然有得學（②③④）。

### 5.3 步步的「學習筆記」（累積機制）

**設計：** 步步把學到的事記在一本可見的筆記本裡，孩子隨時可以翻。

**為什麼重要：**
- 這是**成就感的具體化**——孩子能看見「我教會牠這麼多」
- 這是**分享的素材庫**——孩子可以挑一頁給家長看
- 這是**自我認識的鏡子**——孩子會發現自己的模式（「原來我常常說⋯」）

**呈現規格：**
- 手寫感、有塗鴉、不完美（避免像資料庫）
- 依時間排列，可標記「最喜歡的」
- **不做統計、不顯示數量、不設收集目標**（否則變回集點）

> ⚠️ 明確禁止：「你已經教會步步 20 件事！再教 5 件解鎖⋯」

### 5.4 每日學習量的節制

**規則：每天最多 1 件，且允許「今天沒學到什麼特別的」。**

理由：
- 每天都學到大量東西 → 不真實 → 信任崩壞
- 允許「平淡的一天」→ 反而讓「學到東西的一天」更有價值
- 避免變成需要「餵養」的機制

**平淡日的處理：**
```
「今天沒什麼特別要記的，就是普通的一天。這樣也不錯。」
```

## 六、LLM 導入：五大風險與對策

### 6.1 為什麼需要 LLM

範本文案無法做到「真實的、具體的、回應孩子原話的學習」。這個機制的價值**完全建立在真實性上**，因此 LLM 是必要的。

但以下五項風險必須在架構層級處理。

---

### ⚠️ 風險一：諂媚（Sycophancy）— 最嚴重

**問題：** LLM 經過人類偏好訓練後，有強烈的討好傾向。它的預設輸出就是：

> 「哇！你好棒！你好聰明！這個想法太厲害了！」

**這直接違反本產品最核心的文案原則**——能力讚美（Mueller & Dweck, 1998：導致失敗後低堅持、低享受、更差表現）。

**這不是 prompt 能完全解決的。** 諂媚是模型的訓練後傾向，在長對話中特別容易復發。

**三重防護架構：**

```
第一層｜System Prompt 約束
  - 明確禁用詞清單寫入 system prompt
  - 提供大量正反範例（few-shot）
  - 指定人格：知識略低於孩子、會問笨問題

第二層｜輸出後過濾（Post-generation Filter）★ 必要
  - 規則式關鍵詞攔截：「聰明」「厲害」「棒」「天才」「太強了」等
  - 攔截到即重新生成，重試 2 次後 fallback

第三層｜Fallback 範本
  - 重試失敗則使用預先審核過的範本文案
  - 確保永遠不會輸出違規內容
```

> **第二層是不可省略的。** 只靠 prompt 約束，在真實使用中必然會漏。

---

### ⚠️ 風險二：幻覺（Hallucination）

**問題：** 步步「學到」孩子根本沒說過的事，或編造事實性知識。

**對策：**
- **強約束 prompt：** 只能從孩子本次輸入的內容中提取，禁止推論、禁止補充外部知識
- **可回溯性檢查：** 步步學到的內容必須能對應到孩子原話的片段
- **允許「沒學到」：** 明確告知模型，若孩子輸入太少，輸出「今天沒什麼特別要記的」是正確答案
- **事實性知識一律不由 LLM 生成**（「每日一個小疑問」等模組使用人工審核內容）

---

### ⚠️ 風險三：角色崩壞（Persona Drift）

**問題：** 長對話中 LLM 逐漸失去角色設定，開始表現得像成人助理，或知識水平暴增。

**對策：**
- 每次呼叫都重新注入完整角色設定（不依賴對話歷史維持人格）
- 限制單次互動長度（本機制只需 1–2 輪）
- **知識水平上限檢查：** 輸出若出現超出角色設定的詞彙或概念，觸發重新生成

---

### ⚠️ 風險四：過度自我揭露誘導

**問題：** 一個會「向孩子學習」、態度溫暖的 LLM 角色，可能誘導孩子分享過多私人資訊（家庭衝突、負面情緒、個人隱私）。

> 依據：擬社會關係（PSR）愈強，孩子愈信任角色。這是效果的來源，也是風險的來源。

**對策：**
- 步步**不主動追問**私人細節（「為什麼你爸媽會吵架？」← 絕對禁止）
- 敏感主題偵測 → 觸發引導語 + 依安全流程處理
- 孩子的原始輸入**優先儲存於裝置端**，不常駐雲端

---

### ⚠️ 風險五：成本、延遲、離線

**問題：**
- LLM 呼叫有成本，兒童產品的付費意願有限
- 延遲影響體驗（孩子的耐心有限）
- 離線時無法使用，但核心流程必須支援離線

**對策：**

| 情境 | 處理 |
|---|---|
| 每日 1 次呼叫 | 成本可控（每用戶每日 1 次，可用小模型） |
| 延遲 > 3 秒 | 顯示步步「在想事情」的動畫（符合角色設定，且不焦躁） |
| 延遲 > 8 秒 | fallback 到範本 |
| 離線 | 使用範本文案；連線後可補上 LLM 版本 |

## 七、技術架構建議

### 7.1 混合架構（Hybrid）

> **原則：LLM 只負責「這一句」，不負責整個產品的語言。**

| 模組 | 實作方式 | 理由 |
|---|---|---|
| 每日開場、提醒、結束語 | **範本**（已審核） | 高頻、可預測、不需個人化 |
| if-then 引導提問 | **範本 + 少量規則** | 需要嚴格控制引導品質 |
| 歷程問題 | **範本隨機抽選** | 已有文案庫 |
| **步步的學習回應** | **LLM** ★ | 必須真實、具體、個人化 |
| 步步的學習筆記整理 | LLM（低頻，可批次） | 月度回顧時生成 |
| 事實性知識內容 | **人工審核內容庫** | 絕不由 LLM 生成 |

### 7.2 System Prompt 設計要點

```
角色設定：
- 你是步步，一個和孩子差不多大的小生物
- 你的知識比同齡孩子「少一點」，你會不懂很多事
- 你可以問笨問題、可以說「我不知道」

任務：
- 從孩子剛剛說的話裡，找出「一件你不知道的事」
- 用你自己的話說出來，並說明你原本怎麼想
- 如果孩子說得很少，就說「今天沒什麼特別要記的」

嚴格禁止：
- 讚美孩子本身（聰明、厲害、棒、天才⋯）
- 說出孩子沒有提到的內容
- 使用超過小學生程度的詞彙
- 表達失望、難過、期待
- 提到孩子做了幾件事、完成率、連續天數

語氣：
[依年齡層注入不同語氣規格]

範例（正確）：
[3–5 組 few-shot 範例]

範例（錯誤）：
[3–5 組反例，並說明為什麼錯]
```

### 7.3 輸出過濾器規格

```
攔截清單（Level 1，必攔）：
  聰明 / 厲害 / 好棒 / 太強 / 天才 / 完美 / 優秀
  加油 / 繼續保持 / 我以你為榮
  連續 / 天數 / 完成率 / 解鎖 / 升級

攔截清單（Level 2，需檢查上下文）：
  沒關係 / 可惜 / 明天再 / 很好

長度檢查：超過 60 字 → 重新生成（步步話不多）

年齡詞彙檢查：超出設定詞表 → 重新生成

處理流程：
  攔截 → 重新生成（最多 2 次）→ 仍失敗 → fallback 範本
```

## 八、安全與隱私

### 8.1 兒童 LLM 應用的額外要求

| 項目 | 規格 |
|---|---|
| **資料傳輸** | 只傳送當次回應所需的最小內容，不傳送歷史紀錄 |
| **資料保存** | LLM 供應商端設定為**不保留、不用於訓練** |
| **本地優先** | 孩子的原始輸入優先存於裝置端 |
| **家長知情** | Onboarding 明確說明「步步的部分回應由 AI 生成」 |
| **可關閉** | 家長可關閉 LLM 功能，改用純範本模式 |
| **內容過濾** | 供應商端 + 自建雙層安全過濾 |
| **審計日誌** | 保留違規攔截紀錄（去識別化）供品質改善 |

### 8.2 合規注意

- **COPPA / 台灣個資法：** 13 歲以下的資料處理需可驗證的家長同意；LLM 呼叫涉及資料外傳，須明確揭露
- **英國 ICO 適齡設計準則：** 預設最高隱私設定；LLM 功能應為 opt-in 或至少明確告知
- **透明度：** 不宜讓孩子誤以為步步是「真的有意識的生物」。低年級可保留想像空間，但**家長端必須完全透明**

### 8.3 心理健康警訊處理

若孩子的輸入出現自傷意念、嚴重情緒困擾或受虐跡象：

1. **LLM 不處理**——立即切換至預先審核的安全回應
2. 以溫暖、不驚嚇的語氣回應
3. 引導孩子與信任的大人談
4. 依產品安全機制通知家長並提供專業資源

> 此流程需另立文件，並經兒童心理專業人員審核。**絕不可由 LLM 即興生成危機回應。**

## 九、文案範例庫

### 9.1 孩子分享了方法

```
① 你剛剛說「先寫最討厭的」——我以前都想說要按順序寫耶。
② 原來可以先跳過不會的。我一直以為要卡在那裡。
③ 你把大的拆成三個小的。我沒想過可以這樣。
```

### 9.2 孩子分享了自我認識

```
① 你說你早上比較有精神。我還以為大家都一樣。
② 原來你洗完澡之後比較坐得住。這個我記下來。
③ 你說吃飽會想睡——那難怪你把它排在晚飯前。
```

### 9.3 孩子分享了感受

```
① 你說卡住的時候會想放棄，但過一下就好了。原來會過去喔。
② 你說做之前很煩，做完就還好。這個我要記起來。
```

### 9.4 孩子分享了知識

```
① 直笛高音要按半孔？我完全不知道欸。
② 原來蝸牛不是昆蟲。我一直以為是。
```

### 9.5 孩子今天沒做（關鍵情境）

> **這是驗證機制是否正確的試金石。步步在這裡必須一樣能學到東西。**

```
① 你說你今天太累了，所以先休息。原來累的時候可以先不做。
② 你今天選了先睡覺。我覺得這也是一種決定。
③ 你說那個時間點根本不可能——那我學到一件事：計畫要配合真實的一天。
```

> 🚫 **絕對禁止：**
> - 「今天沒學到新東西⋯」（暗示孩子讓牠失望）
> - 「沒關係，明天再教我！」（隱性施壓）

### 9.6 孩子說得很少 / 跳過

```
① 今天沒什麼特別要記的，就是普通的一天。這樣也不錯。
② 好，那今天就這樣。
```

### 9.7 分享給家長的引導

```
① 這件事要不要跟家裡的人說？（不想也可以）
② 我把它記在筆記本了。你想給誰看嗎？
```

## 十、驗證指標

### 10.1 這個機制是否有效？

| 指標 | 判讀 |
|---|---|
| 孩子在夜晚回顧的**回答長度**是否增加 | 上升 = 分享慾提升 ✅ |
| 孩子主動翻閱「學習筆記」的頻率 | 上升 = 成就感具體化成功 ✅ |
| 孩子主動分享給家長的比例 | 上升 = 達成設計目標 ✅ |
| IMI 勝任感子量表分數 | 上升 = 徒弟效應生效 ✅ |

### 10.2 這個機制是否變質？

> **以下任一訊號出現，代表「學習」已退化為酬賞，需立即介入。**

| 警訊 | 判讀 | 行動 |
|---|---|---|
| 孩子出現「我要讓步步學到東西」的語言 | 學習變成目標 → 外在動機化 | 弱化學習的顯著性，強化「平淡日也 OK」 |
| 「沒做事」的日子，孩子的分享率顯著低於「有做事」的日子 | 孩子已認知學習與完成任務掛鉤 | 檢查文案，強化非任務類學習（②③④類） |
| 孩子詢問「我教了步步幾件事？」 | 收集心態出現 | 確認未意外顯示數量統計 |
| 高年級孩子回饋「步步很假」 | 真實性崩壞 | 檢查 LLM 輸出是否過度誇張或編造 |

### 10.3 LLM 品質監測

- **攔截率：** 輸出過濾器的觸發比例（若持續 > 15%，需重新調校 prompt）
- **Fallback 率：** 落到範本的比例（目標 < 5%）
- **回應延遲：** P95 延遲
- **人工抽樣審核：** 每週抽樣 100 則，由文案負責人依第七章檢核表評分

## 十一、分階段導入建議

### 階段 A：純範本驗證（2 個月）

**先不用 LLM。** 用規則式範本實作最簡版本，驗證機制本身是否受歡迎。

- 依孩子勾選的類別，抽取對應範本
- 觀察：孩子的回答長度、分享率是否提升

**決策點：** 若機制本身沒有引起孩子興趣，導入 LLM 也救不了——先修機制。

---

### 階段 B：LLM 小規模試行（2–3 個月）

- 導入 LLM + 完整三重防護
- 限定 10–15% 用戶，且需家長 opt-in
- 密集人工審核（每則都看）
- 對照組維持範本，比較兩組的分享率與 IMI 分數

**決策點：** LLM 版本的真實性與品質是否顯著優於範本版本？成本是否可承受？

---

### 階段 C：全面導入 + 學習筆記（3 個月）

- LLM 開放全用戶（保留家長關閉選項）
- 上線「步步的學習筆記」
- 上線月度回顧的 LLM 整理

---

### 階段 D：長期監測

- 持續監測第 10.2 節的變質警訊
- 「暫停使用研究」時特別觀察：孩子是否仍保有分享意願

## 結語

這個提案的價值，在於它**把孩子從接受者變成給予者**。這是整個產品裡唯一一個關係反轉的環節，也因此是勝任感最濃的一個。

但它的成敗，取決於一個看似微小的設計決定：

> **步步在孩子什麼都沒做的那天，還學不學得到東西？**

如果學得到，這是一個滿足三大需求的優秀機制。
如果學不到，它就只是一個包裝得比較文雅的集點系統。

至於 LLM——它是實現真實性的必要工具，但必須被**限制**而非**發揮**。步步不需要聰明，牠需要的是不懂。一個什麼都懂的 AI，沒辦法讓孩子覺得自己教會了牠什麼。
